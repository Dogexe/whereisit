# WI-017 — Accent palette: Blue replaces Purple, Coral shifts warm

Status: Ready

Spec: `docs/specs/color-palette-refresh.md`

Codex profile: terra-medium

## Goal

The "Purple" accent option is relabeled "Blue" with a hue shifted from
violet toward a cleaner blue (per the user's reference image); "Coral"
shifts warmer/orange so it no longer reads as close to the new
expense-red (WI-016). No new accent option, no change to how accent
selection is stored or applied.

## Acceptance criteria

- [ ] `theme.js`'s `ACCENT.purple` entry gets new `base`/`c600`/`c700`/
      `heroStart`/`heroEnd` hex values reading as blue, not violet. The
      object key stays literally `purple` (see spec decision 1 — no data
      migration).
- [ ] `theme.js`'s `ACCENT.coral` entry gets new `base`/`c600`/`c700`/
      `heroStart`/`heroEnd` hex values shifted warm/orange-amber, moved
      away from its current red-leaning hue.
- [ ] `i18n.js:52`'s `accentColorPurpleOpt` becomes `["น้ำเงิน", "Blue"]`.
      `accentColorCoralOpt` stays `"Coral"`/`"ส้ม"` (label unchanged, only
      its hex changes).
- [ ] Every new base color clears ≥4.5:1 contrast with white text
      (matches the existing constraint documented in `theme.js`'s header
      comment for coral), measured in a real browser, not hand-converted.
- [ ] `docs/specs/coral-rebrand-and-logo.md` gets a short pointer note
      added noting its hex values were superseded here.
- [ ] Existing related behavior remains unchanged.

## UX / design references

- Follow `docs/UX.md`.
- Match existing: the accent-switching mechanism itself
  (`applyTheme()`/`settings.js`'s radio group) is unchanged — this ticket
  only edits the two hex sets and one label string.
- Reuse: `theme.js`'s existing `ACCENT` object shape; `settings.js`'s
  existing accent-dot CSS already reads `var(--color-accent)` per the
  WI-010 lesson recorded in `docs/SOT.md` — no change needed there.
- New design primitives required by this ticket: none.
- Mobile (<1024px) behavior: Settings > Appearance > Accent color row,
  same expand-in-place control as today.
- Desktop (>=1024px) behavior: same control, no desktop-specific
  difference exists today.

## Implementation guidance

- Likely files: `src/theme.js` (the `ACCENT` const and its header
  comment), `src/i18n.js:52`, `docs/specs/coral-rebrand-and-logo.md`.
- Likely functions: none — `ACCENT` is a plain data object, no logic
  change.
- Existing pattern to reuse: `theme.js`'s own header comment documents the
  exact verification method used to tune coral originally ("Resolved via
  canvas getImageData against real Chrome, not hand-converted") — repeat
  that method for both new hue sets rather than picking values by eye.
- Known invariants: `heroStart`/`heroEnd` feed the Home hero card gradient
  specifically and may differ from `base`/`c700` (purple already does
  this) — don't collapse them back to a flat pair without checking how
  the gradient reads on the hero card.
- Do not change: the `ACCENT` object's key names (`coral`/`purple`),
  `state.accentColor`'s possible values, `applyTheme()`'s structure,
  `settings.js`'s radio `value` attributes.
- Escalate back to Claude if: a chosen blue/coral base can't simultaneously
  clear 4.5:1 white-text contrast and look visually distinct from
  `--color-expense-700`/`--color-income-700` in both themes — that's a
  design tradeoff, not an implementation detail.
