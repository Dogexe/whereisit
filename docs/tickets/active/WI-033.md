# WI-033 — Give themed color tokens one owner: styles.css

Status: Ready

Spec: none — pure refactor, no product change. The one standing decision it
reverses (`docs/UX.md`'s Design-token ownership) is recorded under
Dependencies; maintainer approval for it was granted 2026-09-12.

Codex profile: terra-medium

Profile reason: the work is mechanical transcription of values that already
exist, with no state, persistence, or sync involved. The risk here is a
dropped token, which verification catches — not reasoning depth. (The Risk
tier below is High for a different reason and is deliberately not coupled to
this field.)

Risk tier: High

## Goal

Every themed color token is declared once, in `styles.css`. `applyTheme()`
stops writing colors and shrinks to setting two attributes on `<html>` plus
the `theme-color` meta tag. The "keep these two files in sync by hand"
requirement disappears.

## Why now

The two-owner model has already drifted, and it is visible on every cold load:

| Token | `styles.css:69` (first paint) | `theme.js:100` (runtime, coral) |
|---|---|---|
| `--hero-gradient-end` | `#74311A` (dark brown) | `#D6A44C` (gold) |

Home's hero card paints coral→brown, then repaints coral→gold when `main.js:52`
runs. Nothing detects this: `styles.css:123-124` says the `:root` block is
"kept in sync with theme.js's light object", and that is enforced only by
whoever remembers to.

## Acceptance criteria

- [ ] `applyTheme()` (`theme.js:104-198`) contains **no** `setProperty` call.
      It sets `document.documentElement.dataset.theme` to `"dark"`/`"light"`,
      sets `.dataset.accent` to `state.accentColor`, and keeps the existing
      `themeColorMeta` update (`theme.js:196-197`) — that one must stay in JS,
      a meta attribute is not settable from CSS.
- [ ] The `light`/`dark` objects (`theme.js:129-130`) and the `ACCENT` map
      (`theme.js:99-102`) are deleted, not left unused.
- [ ] `color-scheme` moves to CSS (`:root { color-scheme: light }` and
      `color-scheme: dark` in the dark block), replacing `theme.js:133`.
- [ ] `styles.css` gains a `:root[data-theme="dark"]` block declaring exactly
      these 17 tokens — the nine surfaces, the seven semantics that differ by
      theme, and the logo ring — at exactly their current runtime values:
      `--color-bg:#111216`, `--color-card:#1f2027`, `--color-surface:#282a31`,
      `--color-divider:rgba(255,255,255,0.10)`,
      `--color-border:rgba(255,255,255,0.16)`,
      `--color-muted:rgba(245,245,247,0.62)`,
      `--color-tertiary:rgba(245,245,247,0.42)`,
      `--color-tabbar-inactive:rgba(245,245,247,0.42)`,
      `--color-text:#f5f5f7`, `--color-income:#34c98a`,
      `--color-income-700:#4ADE80`, `--color-expense:#ff7a68`,
      `--color-expense-700:#F87171`, `--color-warning:#f5b95a`,
      `--color-chart-5:#4fd6c4`, `--color-chart-6:#e768ab`,
      and `--logo-ring-color:#ffffff`.
- [ ] `styles.css` gains a `:root[data-accent="purple"]` block declaring
      `--color-accent:#6247ea`, `--color-accent-600:#4f34d6`,
      `--color-accent-700:#3f28ab`, `--hero-gradient-start:#6149ea`,
      `--hero-gradient-end:#409ce9`. Coral stays the bare-`:root` default —
      no `[data-accent="coral"]` block.
- [ ] **`styles.css:69`'s `--hero-gradient-end` is corrected to `#D6A44C`.**
      This is the one intended visual change in the ticket: it removes the
      brown→gold flash on first paint. Every other token's rendered value is
      byte-identical before and after, in both themes and both accents.
- [ ] `--logo-ring-color`'s light value stays the literal string
      `var(--color-accent)` (`styles.css:77`), so it keeps following the
      accent preference; only dark mode pins it to `#ffffff`.
- [ ] The derived tokens are **not** moved into either new block and are not
      duplicated: `--color-accent-tint`, `--shadow-accent`,
      `--color-income-tint`, `--color-expense-tint`, `--color-warning-tint`,
      `--color-chart-5-tint` are `color-mix()` over a base declared on the
      same element, so they re-resolve against the overridden base on their
      own. Confirm this in the browser rather than assuming it.
- [ ] `--color-income-tint-fg`, `--color-chart-5-tint-fg`,
      `--color-warning-text`, `--hero-negative-gradient-start`/`-end` and
      `--color-logo-amber` are untouched — they are deliberately
      theme-invariant and have comments in `styles.css` saying why.
- [ ] `docs/UX.md:30-45` ("Design-token ownership") is rewritten to name
      `styles.css` as the sole owner. The rule "Editing a themed color only in
      `:root` changes the first paint and nothing else" is now false and must
      go. The `*-tint` rules and the `-tint-fg` contrast rule stay as-is —
      this ticket does not change them.
- [ ] The comments in `styles.css` that describe the old two-owner model are
      brought in line. Two are *only* about that and go away entirely:
      `:57-59` (accent fallback) and `:65-67` (hero gradient fallback), as does
      `:122-124` ("surfaces (swapped by applyTheme)" plus the WI-018 "kept in
      sync with theme.js's light object" note). Two others also carry design
      rationale that must survive — `:79-81` (why the `-700` pair exists for AA
      contrast on `--color-card`) and `:113-118` (why chart-5/6 were chosen far
      in hue from both accents). Edit those down to drop only the
      "theme.js overrides this / pre-JS fallback" clauses; keep the reasoning.
- [ ] No color value in the app changes except `--hero-gradient-end`'s first
      paint, and no new token is introduced.

## Implementation guidance

- **Likely files:** `src/theme.js`, `styles.css`, `docs/UX.md`. Nothing else
  should need to change.
- **`applyTheme()`'s two call sites stay as they are:** `main.js:52` (boot) and
  `settings.js:445-446` (the accent and appearance radios). Both still need to
  run — they now flip attributes instead of writing 22 properties.
- **Why attributes on `<html>` and not a class:** two independent axes (theme,
  accent) read more clearly as two attributes, and `:root[data-theme="dark"]`
  outranks bare `:root` on specificity without `!important`.
- **The old code wrote inline styles on `documentElement`,** which outrank any
  stylesheet rule. Deleting the `setProperty` calls is sufficient — inline
  styles are not persisted, so there is no stale state to migrate and no
  cleanup pass needed on upgrade.
- **Existing regression guard:** `e2e/dark-mode.spec.js:4-29` already asserts
  `getComputedStyle(document.body).backgroundColor` is exactly
  `rgb(238, 240, 244)` light / `rgb(17, 18, 22)` dark after toggling the
  Settings switch. It is written against computed style, not against
  `theme.js`, so it should pass unmodified — if it needs editing to pass,
  something is wrong with the refactor, not with the test.
- **Known invariant:** `rowTone()`/`GOAL_TONES` (`categories.js`) and
  `CHART_COLORS` (`derived.js`) pass `var(--token)` **strings** into inline
  `style=` attributes. They must keep doing that — do not resolve them to hex.
- **Do not change:** any color's rendered value; the derived `*-tint` /
  `-tint-fg` tokens; `index.html:16`'s meta tag markup; the accent radio /
  appearance radio wiring in `settings.js`.
- **Escalate back to Claude if:**
  - a `*-tint` does not re-resolve against an overridden base (that would
    invalidate the whole approach — stop, don't work around it by
    duplicating tints into the dark block);
  - any token turns out to be read from JS as a hex rather than a
    `var()` string;
  - the first paint flashes in a *new* place after the change.

## Out of scope

- Changing any color, contrast ratio, or palette decision. This ticket moves
  values; it does not retune them. `--hero-gradient-end`'s first paint is a
  correction to match the already-shipped runtime value, not a new choice.
- Honouring the OS `prefers-color-scheme`. The app's dark mode is an explicit
  persisted preference (`state.dark`), and this ticket does not change that.
- The other findings from the same audit pass (the six `pull*` functions in
  `sync.js`, the five `delete*` functions in `settings-*.js`, the six sheets'
  duplicated plumbing). Separate tickets if wanted.
- `--color-logo-amber` and the `-tint-fg` tokens.

## Dependencies

**Maintainer approval to reverse `docs/UX.md:30-45` — granted 2026-09-12,
before this ticket moved to `Ready`.** That section names `theme.js`'s
`applyTheme()` the runtime owner of every themed color and `styles.css`'s
`:root` the first-paint fallback only; this ticket inverts that, making
`styles.css` the sole owner.

`docs/UX.md` is deliberately **not** edited ahead of the implementation. The
approval authorizes the reversal; the doc changes in the same commit as the
code, because a `UX.md` that names `styles.css` the owner while `theme.js`
still writes 22 properties would be actively misleading to the next session.
Rewriting that section is an acceptance criterion above, not a prerequisite.

No code dependencies. WI-030/031/032 touch Home's bill rows and the bills
schema; they do not touch the token layer, so this can land in any order
relative to them.
