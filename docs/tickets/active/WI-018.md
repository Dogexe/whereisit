# WI-018 — Base surface retune (light + dark bg/card/surface/divider/border)

Status: Ready

Spec: `docs/specs/color-palette-refresh.md`

Codex profile: sol-high

Profile reason: retuning `bg`/`card`/`surface`/`divider`/`border` risks
silently breaking several already-tuned contrast floors documented inline
in `theme.js` (`tabbarInactive` vs `bg` at ≥3:1, `muted`/`tertiary` vs
`bg`/`card`, `-700` amount variants vs `card`) since those were computed
against the *current* hex values — this is a subtle-regression risk
class, not ordinary bounded UI work.

## Goal

Light and dark mode's base surface tokens (`bg`, `card`, `surface`,
`divider`, `border`) are retuned toward the reference image's clean,
high-contrast card-on-tinted-background look — light mode as a refinement
(it's already close), dark mode as a natural dark counterpart of the same
feel — with every dependent contrast ratio re-verified, not assumed.

## Acceptance criteria

- [ ] `theme.js`'s `light` and `dark` objects (`applyTheme()`) get new
      `bg`/`card`/`surface`/`divider`/`border` values in both themes.
      `muted`/`tertiary`/`tabbarInactive`/`text` may also change if needed
      to keep their documented contrast floors against the new bg/card —
      but only if needed, not as a default.
- [ ] Every ratio `theme.js`'s existing inline comments document a floor
      for is re-measured at the new values, in both themes, and recorded
      in this ticket's Review notes: `tabbarInactive` vs `bg` (≥3:1),
      `muted`/`tertiary` vs `bg` and `card`, income-700/expense-700 vs
      `card` (≥4.5:1).
- [ ] No card visually blends into its page background, and no
      divider/border becomes invisible, in either theme, across Home,
      Transactions, Add sheet, Insights, and Settings.
- [ ] No new token names introduced — only the existing eight per-theme
      keys change value.
- [ ] Existing related behavior remains unchanged.

## UX / design references

- Follow `docs/UX.md`, specifically "Measured, not eyeballed" and the
  Design-token ownership section (`theme.js` is the runtime owner of every
  themed color; `styles.css`'s `:root` is only the pre-JS fallback and
  must be updated to match so first paint isn't stale).
- Match existing: this is a value-only retune of the existing surface
  ladder (page → card → inset), not a new layout or new surface role.
- Reuse: the existing `applyTheme()` structure and `:root` fallback
  mechanism.
- New design primitives required by this ticket: none.
- Mobile (<1024px) behavior: no layout change, color only.
- Desktop (>=1024px) behavior: no layout change, color only.

## Implementation guidance

- Likely files: `src/theme.js` (`light`/`dark` objects in `applyTheme()`),
  `src/styles.css`'s `:root` fallback block (search for the same
  `--color-bg`/`--color-card` etc. declarations — these must be kept in
  sync with `theme.js` per the Design-token ownership rule, or first paint
  will show stale colors before JS runs).
- Likely functions: `applyTheme()`.
- Existing pattern to reuse: `theme.js`'s own comments document the exact
  contrast-verification method already used for every tuned token in this
  file (canvas `getImageData` against real rendered Chrome) — use the same
  method here rather than hand-converting or eyeballing.
- Known invariants: `--color-accent-tint`/`--shadow-accent` are
  `color-mix()` expressions in `styles.css` that auto-derive from
  `--color-accent` — don't hand-edit them, but do confirm they still read
  correctly against the new `card`/`surface` values since `color-mix()`
  mixes toward `white` regardless of theme (see the `*-tint` foreground
  rule in `docs/UX.md`'s Design-token ownership section).
- Do not change: token names, `applyTheme()`'s call signature, anything
  outside the surface/divider/border/muted/tertiary/tabbarInactive/text
  values.
- Escalate back to Claude if: a contrast floor can't be met without also
  changing `muted`/`tertiary`/`tabbarInactive`/`text` beyond a small nudge
  — that's a bigger ripple than this ticket scoped and worth a second
  opinion before proceeding.
