## Goal

Browser Back dismisses the Transactions Filters, Insights Filters, Export and
Import sheets, the same way WI-026 made it dismiss the Add sheet.

## Acceptance criteria

- [ ] Each of the four sheets pushes an overlay history entry when it opens and
      releases it when it closes, using WI-026's `src/overlay-history.js`:

      | Sheet | Push at | Release in |
      |---|---|---|
      | Transactions Filters | `transactions.js:326` | `closeTxFilterSheet` (`transactions.js:307`) |
      | Insights Filters | `insights.js:160` | `closeInsightsFilterSheet` (`insights.js:242`) |
      | Export | `export-sheet.js:69` | `closeExportSheet` (`export-sheet.js:47`) |
      | Import | `openImportSheet` (`import-sheet.js:37`) | `closeImportSheet` (`import-sheet.js:47`) |

- [ ] Each sheet uses its **own distinct key**, so two keys can never collide
      on the stack.
- [ ] The release call goes in the single named close function each sheet
      already funnels every dismissal through — close button, backdrop tap,
      Escape, swipe-down, **and** the action-completed paths
      (`export-sheet.js:82`/`:89`/`:93` after CSV/JSON/Sheets export,
      `import-sheet.js:260` after a commit). No per-path release calls.
- [ ] The `onPop` callback is the **named close function**, never a closure
      over a captured backdrop element (see Implementation guidance).
- [ ] Back with any of the four open closes that sheet, keeps the URL, and
      stays in the app.
- [ ] Every non-Back dismissal of each sheet returns `history.length` to its
      pre-open value, including the action-completed paths.
- [ ] `src/screens/settings.js` is still **not** modified, and
      `e2e/nav.spec.js:73-108` still passes unchanged.
- [ ] The Add sheet's behavior from WI-026 is unchanged.
- [ ] No new CSS, class, `STRINGS` key, icon, or visible control.
- [ ] Existing related behavior remains unchanged.

## UX / design references

- Follow `docs/UX.md`.
- Match existing: WI-026's Add sheet adoption — same push-on-open,
  release-inside-the-close-function shape.
- Reuse: each sheet's existing close function. Back becomes a new caller of
  it, not a new close path.
- New design primitives required by this ticket: **none.** Nothing visual
  changes.
- Mobile (<1024px) behavior: Back closes whichever of the four is open.
- Desktop (≥1024px) behavior: same. Unlike the Add sheet, these four exist at
  every viewport, and Back-dismisses-the-sheet is correct on both — the owner
  is deliberately viewport-agnostic (spec decision 6).

## Implementation guidance

- **Likely files:** `src/screens/transactions.js`, `src/screens/insights.js`,
  `src/screens/export-sheet.js`, `src/screens/import-sheet.js`, plus e2e
  coverage. No new module, no `settings.js`.
- **Existing pattern to reuse:** WI-026's Add sheet wiring, verbatim in shape.
  Read `openAddSheet`/`closeAddSheet` after that ticket ships and copy it.
- **Why `onPop` must be the named function, not a closure:** all four sheets
  render inside `#screen`'s `innerHTML`, which `renderScreen()` fully rebuilds
  — including on the 25-second background sync tick (`main.js:97`). The open
  state survives that (the `state.*SheetOpen` flag drives the `hidden`
  binding), but the DOM node does not. Every close function already looks its
  backdrop up fresh by id and documents why (`transactions.js:304-306`,
  `export-sheet.js:45-46`, `import-sheet.js:45-46`). A captured element would
  be detached and silently do nothing.
- **Insights is the awkward one, in two ways.** Its sheet fully regenerates its
  own markup on almost every field change while open
  (`renderBreakdownFilterSheet`, `insights.js:258`), so nothing may be wired
  once at setup (`docs/ARCHITECTURE.md:89-96`). And it has two close paths that
  differ — `dismiss` (`insights.js:264`) re-renders afterward, the Escape
  listener (`:248`) does not. Both reach `closeInsightsFilterSheet`
  (`:242`), which is why the release call belongs there and nowhere else.
- **Relevant tests:**
  - `e2e/filters.spec.js` — existing Transactions/Insights filter-sheet
    coverage; the natural home for the new assertions on those two.
  - `e2e/csv-import.spec.js` — drives the Import sheet through a real commit,
    which is the `import-sheet.js:260` close path.
  - `e2e/nav.spec.js:73-108` — the Settings sub-page history round trip;
    regression guard that `settings.js` is still untouched.
- **Do not change:** `src/screens/settings.js`, `router.js`'s `setTab`, the
  Manage sheet, `src/overlay-history.js` itself (if it needs a change, that is
  an escalation, not a quiet edit), or any sheet's dismissal semantics.
- **Escalate back to Claude if:**
  - any of the four turns out to have a dismissal path that does *not* route
    through its named close function;
  - two of these sheets can be open simultaneously (the spec's single-stack
    assumption says they cannot);
  - adopting Insights' sheet appears to require restructuring
    `renderBreakdownFilterSheet`;
  - `src/overlay-history.js` needs an API change to accommodate any of them.
