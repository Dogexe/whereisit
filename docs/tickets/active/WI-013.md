# WI-013 — Accessible names for the mobile tab bar

Status: Ready

Spec: `docs/specs/accessible-names-and-focus-indicators.md`

Codex profile: terra-medium

## Goal

Give each of the five `#tabbar` buttons a localized accessible name, so the
app's primary navigation is usable by a screen reader. No visual change.

## Acceptance criteria

- [ ] Each `#tabbar` button exposes a non-empty accessible name.
- [ ] The names come from the existing `STRINGS` keys `tabHome`, `tabTx`,
      `tabAdd`, `tabInsights`, `tabSettings` — no new `STRINGS` entries, and
      no hardcoded Thai or English text anywhere.
- [ ] Names follow a language switch, via `renderChrome()`'s existing
      re-run on language change (spec Decision 1.1). No new listener.
- [ ] `#sidebar`'s buttons are unchanged — they already have visible
      `<span data-l>` labels and are not part of this defect.
- [ ] The tab bar renders no visible text, and its buttons' rendered
      geometry is unchanged at every width (spec Decision 1.2).
- [ ] Icons stay `aria-hidden="true"`; the name lives on the button.
- [ ] Existing related behavior remains unchanged — active-state
      highlighting, the Add button's sheet-open behavior, and the fact that
      Add does not change `state.tab`.

## UX / design references

- Follow `docs/UX.md`.
- Match existing: `renderChrome()`'s existing `data-l` localization loop in
  `screens/router.js`.
- Reuse: the `STRINGS`/`L()` mechanism and the five existing tab keys.
- New design primitives required by this ticket: none.
- Mobile (<1024px) behavior: the tab bar is the visible nav; this is where
  the defect is.
- Desktop (>=1024px) behavior: the tab bar is `display: none` and the
  sidebar is visible. Both navs are always in the DOM, so the labelling
  must be correct regardless of which is shown.

## Verification

- [ ] E2E: every `#tabbar` button has an accessible name matching the
      active language's `STRINGS` value — assert the actual strings, not
      just non-emptiness.
- [ ] E2E: switching language in Settings updates all five names.
- [ ] E2E regression: no visible text in the tab bar; button geometry
      unchanged.
- [ ] `npm test`
- [ ] `npm run test:e2e`
- [ ] `npm run build`
- [ ] Complete diff inspected for unrelated changes.

## Out of scope

- `aria-current` on the active nav button — real, but a separate
  requirement (see the spec's Out of scope).
- Restoring visible tab bar labels. The icon-only design is deliberate.
- Any change to `#sidebar`, to focus indicators (that is WI-014), or to
  `.nav-btn`'s styling.

## Dependencies

None. Independent of WI-014, though the two touch the same nav buttons —
implement sequentially, not in parallel.
