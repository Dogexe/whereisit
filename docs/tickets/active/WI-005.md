# WI-005 — Apple-style swipe actions on Settings' Manage rows

Status: Ready

Spec: `docs/specs/settings-manage-swipe-and-sheet.md` (see "Revision:
Apple-style colored full-height actions + full-swipe-to-delete")

Codex profile: terra-medium

## Goal

Apply the same Apple-style colored full-height action buttons and
full-swipe-to-delete gesture from WI-004 (transaction rows) to Settings'
Manage rows (Budgets, Bills, Categories, Accounts, Goals), adapted for
their variable action count (2 or 3 buttons) and whole-row drag surface.

## Acceptance criteria

- [ ] `manageSwipeWrapHtml`'s reveal width formula changes from
      `20 + actionCount * 34` to `actionCount * 64` (edge-to-edge, no gap
      math), matching WI-004's 64px-per-button sizing.
- [ ] Every action button renders full-height, `border-radius: var(--radius-md)`,
      no visible circular button shape remaining.
- [ ] Delete uses `var(--color-expense)` background + white icon. Edit and
      Accounts' Archive/Unarchive both use `var(--color-border)` background +
      `var(--color-text)` icon (differentiated only by their own icon). No
      new color values/tokens introduced.
- [ ] Full-swipe-to-delete: dragging past 65% of `.manage-row-wrap`'s own
      width and releasing there calls the existing delete flow for that
      section immediately (existing Undo toast, no new confirmation).
      Applies correctly regardless of button count (2 for
      Budgets/Bills/Categories/Goals, 3 for Accounts) — Delete is always
      the last/rightmost action.
- [ ] Releasing between the reveal point and the 65% commit threshold snaps
      back to fully open (not closed, not deleted).
- [ ] Goals: only Edit/Delete are affected (2-button case) — Contribute
      stays outside the swipe wrapper, unchanged.
- [ ] Icon-only buttons, no visible text labels added.
- [ ] Desktop (1024px+) Settings layout is pixel-unchanged for every
      section (always-visible icons, inline forms — untouched).
- [ ] Light and dark mode both render correctly.

## Verification

- [ ] `npm test`
- [ ] `npm run test:e2e`
- [ ] `npm run build`
- [ ] Real-browser check at mobile width (<1024px) per the spec's
      verification plan, covering at least one 2-button section and
      Accounts (3-button): correct button styling and sizing, full-swipe
      commit deletes immediately with working Undo, release between reveal
      and commit snaps back open, and desktop (1024px+) is unaffected for
      every section.

## Out of scope

- Everything WI-004's own "Out of scope" list already covers.
- Any change to `manageSwipeWrapHtml`'s function signature beyond the
  reveal-width formula, or to `wireManageRowSwipe`'s existing snap-threshold
  logic beyond adding the full-swipe commit check.
- Any change to the desktop (1024px+) Settings layout, forms, or row
  appearance.

## Dependencies

None — independent of WI-004 (separate files), but implementing WI-004
first is recommended so this ticket can reuse its finalized button
colors/sizing instead of re-deriving them.
