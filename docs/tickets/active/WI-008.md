# WI-008 — Settings sub-page navigation model

Status: Ready

Spec: `docs/specs/settings-chatgpt-style-navigation.md`

Codex profile: sol-high

Profile reason: introduces the app's first `popstate`/`pushState`
handling and rewrites a screen-wide state field, and the failure mode
(a navigation ordering race between the back arrow, the hardware Back
button, and a main-tab switch) is exactly the class this project's
rules single out as unreliable to reason about from the code alone.

## Goal

Turn Settings' five Manage sections and the Security section from
inline `<details>` accordions into real sub-pages with a back arrow and
working browser/hardware Back, while leaving desktop's master–detail
split and every existing Settings action working exactly as today.

**Structure only.** This ticket deliberately reuses the current row
styling, `iconAvatar()` icons, profile row and section labels
unchanged — the new visual language is `WI-009`. A reviewer should be
able to read this diff as pure navigation work.

## Acceptance criteria

- [ ] `state.settingsActiveSection` is replaced by
      `state.settingsSubPage`, defaulting to `null`.
      `state.settingsGroupOpen` is deleted, along with the `toggle`
      listeners that maintained it.
- [ ] Below 1024px with `settingsSubPage === null`, Settings renders a
      root list: the existing profile row, the existing Display and
      Sync & Data panels inline, and navigation rows for Budgets,
      Bills, Goals, Categories, Accounts and Security. Each navigation
      row shows the section's icon, its label, its item count where one
      exists today, and a `chevron-right`. No `<details>`/`<summary>`
      element remains in the Settings markup.
- [ ] Below 1024px with `settingsSubPage` set, Settings renders only
      that section: a header row with a back arrow, the section title,
      and that section's existing Add button where it has one, followed
      by the section's existing rows rendered by their existing
      `xRowHtml()` functions with no changes to those functions.
- [ ] Opening a sub-page below 1024px calls
      `history.pushState({ settingsSubPage: <id> }, "")` with **no URL
      argument** — the URL must not change.
- [ ] The back arrow and a main-tab switch away from Settings both
      close an open sub-page by calling `history.back()` only; the
      `popstate` handler is the single place that clears
      `state.settingsSubPage` and re-renders.
- [ ] The `popstate` handler is a no-op when no sub-page is open, and
      does not interfere with the existing OAuth
      `history.replaceState` calls in `main.js`.
- [ ] At 1024px and up: no sub-page rendering, no back arrow, and no
      `pushState` call ever happens. The nav column and detail panes
      work exactly as today, driven by `state.settingsSubPage`, with
      `null` selecting the `display` pane. `styles.css`'s
      `.settings-layout[data-active="…"]` selectors are updated to the
      new field's values.
- [ ] Add/edit/delete for all five Manage sections still works from
      inside a sub-page, including the mobile shared sheet
      (`renderManageSheet`) and its icon picker. `renderManageSheet`,
      `wireInlineCrud`, and the six `xFormHtml()` modules are not
      modified.
- [ ] Swipe-to-reveal actions on Manage rows still work inside a
      sub-page. `manage-row-swipe.js` is not modified.
- [ ] Every other Settings action is unchanged: sign in/out, language,
      accent color, dark mode, hide amounts, sync now, bill reminders,
      install prompt, export sheet, import sheet, PIN set/remove.
- [ ] The e2e specs that select the removed markup are updated in this
      ticket, not left failing: `e2e/helpers.js`
      (`openSettingsSection`, `createAccount`), `e2e/accounts.spec.js`
      (the mobile `summary .label` click), `e2e/pin-lock.spec.js`,
      `e2e/category-nesting.spec.js`, `e2e/csv-import.spec.js`.
- [ ] New e2e coverage is added for the mobile navigation itself: drill
      into a sub-page, assert the section's rows are visible and the
      root list is not, then `page.goBack()` and assert the root list is
      back and the app has not navigated away.
- [ ] New i18n strings for the sub-page header's back control
      (`backAria`) are added in both languages.
- [ ] Light and dark mode both render correctly.

## Out of scope

- All visual changes: centered profile header, grouped cards, flat
  monochrome icons, section-label restyling, the red Log out row
  (`WI-009`).
- Expand-in-place Appearance / Accent color / Language rows (`WI-010`).
- History integration for main tab switches, or any URL-addressable
  deep link into a sub-page.
- Any change to `manage-row-swipe.js`, `tx-row.js`, `renderManageSheet`,
  `wireInlineCrud`, or any save/delete/contribute function.
- Any schema, storage, or sync change.

## Dependencies

`WI-005` should land first — it asserts the 1024px+ Settings layout is
pixel-unchanged, which is true today and becomes ambiguous once this
spec's tickets restyle that layout. This ticket does not otherwise
depend on it.
