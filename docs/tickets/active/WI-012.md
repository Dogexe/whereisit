# WI-012 — Make `npm run test:e2e` fail honestly when its browser is unavailable

Status: Ready

Spec: none — small tooling/docs ticket, no product behavior change.

Codex profile: terra-medium

Profile reason: bounded scripting and documentation work. It is
deliberately *not* scoped as a root-cause hunt: the underlying cause
lives in the agent sandbox, which this repository cannot change.

## Background

During WI-008/WI-009 an implementing Codex agent reported
`npm run test:e2e` as **failed** three separate times. It had not
failed. Verified from the same working tree minutes later, the suite
passed 27/27 on every attempt.

What was actually established:

- Playwright's `chrome-headless-shell.exe` was present the whole time,
  at `%LOCALAPPDATA%\ms-playwright\chromium_headless_shell-1234\`,
  installed 2026-08-30 and never removed.
- `@playwright/test` is 1.62.1 and matches the installed `chromium-1234`
  build. `node_modules` was untouched since 2026-08-30, and
  `package.json` / `package-lock.json` were unmodified during the
  session — so no dependency drift.
- In the same runs the agent also could not find `python` (it fell back
  to a Node static server) and could not write a `docs/tickets/active/`
  file that edited fine from outside its sandbox.

Three unrelated capabilities failing at once, all working outside the
sandbox, points at the sandbox rather than at Playwright or this repo.
One thing remains genuinely unexplained and should not be asserted
either way: in one session the agent's *first* e2e run passed 27/27 and
only later runs failed.

The cost is not a broken test suite — it is that a "failed" report was
indistinguishable from a real regression, so every agent-reported e2e
result had to be re-run by hand to be worth anything.

## Goal

Make the difference between "the browser could not be launched" and
"tests ran and failed" unmistakable in the output, and record the known
sandbox limitation so a future agent reports it correctly instead of
claiming a regression.

## Acceptance criteria

- [ ] `npm run test:e2e` performs a preflight check that the Playwright
      browser it is about to use actually resolves, before Playwright
      starts. On failure it exits non-zero with a message that states
      plainly that **no tests were run**, names the expected browser
      path, and gives the exact `npx playwright install chromium`
      command to fix it.
- [ ] The preflight adds no meaningful time to a normal run and does not
      change the suite's behavior when the browser is present:
      `npm run test:e2e` still runs the same 27 tests and still builds
      first, exactly as today.
- [ ] The preflight does **not** silently auto-install the browser.
      Downloading a browser as a side effect of running tests is a
      surprise in CI and on a metered connection; it prints the command
      instead.
- [ ] The preflight resolves the browser through Playwright's own
      resolution rather than a hardcoded absolute path, so it stays
      correct when the pinned Playwright version changes its browser
      build number. `PLAYWRIGHT_BROWSERS_PATH` is honored if set.
- [ ] `AGENTS.md` gains a short note, in its own subsection, recording
      that an agent sandbox may not be able to see the Playwright
      browser or `python`, that this is an environment limitation rather
      than a repository fault, and that an agent which cannot launch the
      browser must report e2e as **not run** rather than as failed.
- [ ] `docs/TESTING.md` cross-references that note wherever it describes
      running the e2e layer.
- [ ] No change to any spec file, to `playwright.config.js`'s projects
      or viewports, or to any existing test.

## Verification

- [ ] `npm test`
- [ ] `npm run test:e2e` — still 27 passed.
- [ ] `npm run build`
- [ ] Simulate the failure and confirm the message: run the preflight
      with `PLAYWRIGHT_BROWSERS_PATH` pointed at an empty temporary
      directory, and confirm it exits non-zero, says no tests were run,
      and prints the install command. **Restore the variable afterwards
      and re-run the suite to confirm it still passes** — do not leave
      the check "verified" against a broken environment.
- [ ] Complete diff inspected for unrelated changes.

## Out of scope

- Fixing the agent sandbox itself. It is not part of this repository
  and this ticket cannot reach it.
- Explaining why one session's first e2e run succeeded and later ones
  failed. That evidence was not captured and guessing at it in code
  would be worse than leaving it unexplained.
- Auto-installing browsers, changing CI, or adding a dependency.
- Any product, schema, storage, or sync change.
