## Goal

Every toast the app shows — including every undo prompt — is announced to a
screen reader, without changing how any toast looks or behaves visually.

## Acceptance criteria

- [x] `index.html` gains one element: `<div id="toastLive" class="sr-only"
      role="status"></div>`, rendered on every page load and never
      `hidden`/`display:none`.
- [x] `showToast(msg)` populates `#toastLive` with `msg`.
- [x] `showToast(msg, undoFn)` populates `#toastLive` with `msg` **and** the
      `l.undoBtn` label, matching what the visible toast reads.
- [x] Calling `showToast` twice in a row with the **same** message
      re-populates the announcer the second time (clear, then set on a later
      tick — a same-value `textContent` assignment is not a mutation and
      announces nothing).
- [x] `#toastLive` is emptied when the toast auto-hides and when Undo is
      clicked.
- [x] `#toast`'s markup, id, class, `hidden` toggle, styles, position, and
      both auto-hide timings (2200 ms / 4000 ms) are unchanged.
- [x] `#toast` is **not** given `aria-hidden` — the Undo button must stay in
      the accessibility tree and focusable.
- [x] No caller of `showToast` changes.
- [x] Existing related behavior remains unchanged.

## Implementation guidance

- **Likely files:** `index.html` (beside `#toast`, line 91), `src/toast.js`
  (the whole module is 19 lines), `e2e/` (new coverage).
- **Likely functions/modules:** `showToast()` (`toast.js:5`) — both the
  populate path and the two hide paths (the `setTimeout` at `toast.js:18`
  and the Undo click handler at `toast.js:12`).
- **Existing pattern to reuse:** `styles.css:679`'s `.sr-only`, whose own
  comment calls it the "standard visually-hidden-but-still-announced
  pattern". It already exists and is already used by `add.js:316`. Do not
  add a second visually-hidden rule.
- **Why not `role="status"` on `#toast` itself** (the roadmap's shorthand):
  `styles.css:1223` is `.toast[hidden] { display: none; }`, so `#toast` is
  out of the accessibility tree except while a toast is up. A live region
  must already be rendered before its content changes for the change to be
  announced. This is spec decision 5 — do not "simplify" it back to a role
  on `#toast`.
- **Relevant tests:**
  - `e2e/transactions-crud.spec.js:113-129` — the existing delete/undo toast
    test; the natural place to model a new announcer test on, and a good
    trigger for an undo-flavored toast.
  - `e2e/pin-lock.spec.js:30` asserts `page.locator("#toast")` is visible.
    That still holds — `#toast` is untouched — but check it still passes.
  - `e2e/focus-indicators.spec.js:22` renders its own synthetic
    `.toast-undo-btn`; unaffected, but do not "tidy" it.
- **Known invariants:**
  - `#toast` and its CSS are out of bounds (see Do not change). The whole
    point of the separate element is that `#toast` needs no change.
  - The Undo button lives inside the *visible* toast and must remain
    focusable — do not move it, duplicate it into the announcer, or
    `aria-hidden` its container.
- **Do not change:** `#toast`'s element, `.toast` / `.toast[hidden]` /
  `.toast-undo-btn` CSS, the auto-hide timings, `.sr-only`'s rule, or any
  `showToast` call site.
- **Escalate back to Claude if:**
  - the announcer appears to need its own CSS rule rather than `.sr-only`;
  - clearing-then-setting the announcer proves unreliable in a way a
    deterministic e2e assertion cannot capture;
  - an existing e2e spec breaks (nothing here should break one).

  (`live.textContent = announcement`) makes the new test fail 4/4. The
  assertion is a real gate, not a tautology.

Note for future verification of this repo: `playwright.config.js` serves the
built `dist/` via `scripts/serve.mjs`, so a mutation to `src/` has no effect
on e2e until `npm run build` is re-run. A mutation test that skips the
rebuild silently exercises the old bundle and reports a false pass.

Optional suggestions (not defects, not acted on):

- The announce tick (`setTimeout(..., 0)` in `toast.js`) has no stored timer
  id, so neither hide path cancels a pending announce. Unreachable at the
  current 2200 ms / 4000 ms timings — a toast cannot be hidden within the
  same tick it is shown — so storing an id would be dead complexity today.
  Worth revisiting only if a future toast is ever dismissed synchronously.
- The announcement joins the message and the Undo label with a single space
  while the visible toast renders them as two elements. These compare equal
  under Playwright's whitespace normalization and read identically to a
  screen reader, so no change is warranted.
