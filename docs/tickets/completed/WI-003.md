# WI-003 — Transactions "Clear all filters" action

Status: Completed

Spec: `docs/specs/transactions-clear-all-filters.md`

Codex profile: luna-low

Profile reason: purely wires the existing, already-tested `clearTxFilters()`
to one new button rendered from an existing container; no new state, no new
derived logic, no persistence/sync involved.

## Goal

Add a "Clear filters" button next to the active-filter chips in Transactions
(`#txActiveChips`) so the user can reset every active filter in one tap
without needing zero results first.

## Acceptance criteria

- [x] `renderActiveFilterChips()` in `src/screens/transactions.js` renders an
      extra button, labeled with the existing `l.clearFiltersBtn` string,
      immediately after the chip buttons, only when `chips.length > 0`.
- [x] That button is wired to the existing `clearTxFilters()` (no new reset
      function).
- [x] The button is not rendered when no filter is active.
- [x] Existing empty-results "Clear filters" button in `renderTxListOnly()`
      is unchanged.

## Verification

- [x] `npm test`
- [x] New Playwright case(s) added to `e2e/filters.spec.js` covering: control
      appears only when a filter is active, clicking it clears all filters
      including search text, and the control is absent again once no filter
      is active.
- [x] `npm run test:e2e`
- [x] `npm run build`
- [x] Complete diff inspected for unrelated changes.

## Out of scope

- Any change to the empty-results "Clear filters" button's own behavior.
- A clear/reset control placed inside the filter sheet itself.
- Any partial/per-facet-group clear action.
- Clearing filters via the chips-row button while the filter sheet is open.
  Confirmed (see Review notes below) that `#clearTxActiveFiltersBtn` is not
  reachable by a real user while `#txFilterSheetBackdrop` is open — the
  backdrop is full-viewport and intercepts pointer events over the chips
  row, and the sheet's focus trap excludes the button from Tab order too.
  No requirement, and no test, should assume or simulate this as an
  achievable user interaction (e.g. via a synthetic `dispatchEvent`).

## Dependencies

None.

## Review notes

**First independent review (Claude, read-only):** AC #1–4 and the empty-
results button's unchanged behavior were confirmed correct, with no
regressions and no unrelated changes in the diff. One confirmed defect: the
now-removed AC "if the filter sheet is open when the user clicks the new
button, the sheet stays open and every control inside it visibly resets"
described a scenario no real user can produce. `#txFilterSheetBackdrop` is
full-viewport (`position: fixed; inset: 0; z-index: 50`) and renders after
`#txActiveChips`, so it fully covers the chips-row Clear button while open;
confirmed empirically with a real (non-synthetic) Playwright `.click()`,
which failed because the backdrop intercepts pointer events at the button's
position, and `document.elementFromPoint()` there resolves to the backdrop.
The sheet's focus trap also excludes the button from Tab order. The e2e
case added for this (`e2e/filters.spec.js`, "active filter clear button
clears search and resets an open filter sheet") used
`.dispatchEvent("click")` to fire the click programmatically, which let the
test pass without the interaction ever being achievable by a mouse, touch,
or keyboard user — it verified the reset handler's internal correctness,
not the acceptance criterion as written.

**Product decision:** Option A — the chips-row Clear button stays reachable
only while the filter sheet is closed; no requirement or test is needed for
the open-sheet case. Spec (`docs/specs/transactions-clear-all-filters.md`,
decision 4 → "Filter sheet reachability") and this ticket's acceptance
criteria/out-of-scope/verification sections have been revised accordingly.

**Remaining work for Codex** (implementation code needs no change — only
the test file):
1. In `e2e/filters.spec.js`, remove the open-filter-sheet portion of the
   "active filter clear button clears search and resets an open filter
   sheet" test: the second `#openTxFiltersBtn` click, the
   `#clearTxActiveFiltersBtn` `dispatchEvent("click")` call, and every
   assertion that follows it (`#txFilterSheetBackdrop` staying visible, the
   type/category/amount controls resetting). Rename the test to reflect
   what it actually covers now (e.g. "active filter clear button clears all
   filters and search").
2. Keep the parts of that test that exercise real, reachable behavior: the
   button absent with no filters active, applying a type + category filter
   and typing search text, closing the sheet (real `Escape` keypress) so
   the button becomes visible, clicking it (a real `.click()`, not
   `dispatchEvent`) and asserting the chips/button/badge/search all clear.
3. Re-run `npm test`, `npm run test:e2e`, `npm run build`; check off this
   ticket's Verification checklist once green.
4. No changes needed in `src/screens/transactions.js` — the implementation
   already matches every preserved acceptance criterion.
