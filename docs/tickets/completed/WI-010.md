# WI-010 — Expand-in-place Appearance / Accent color / Language rows

Status: Completed

Spec: `docs/specs/settings-chatgpt-style-navigation.md`

Codex profile: terra-medium

## Goal

Turn the Display group's three multi-option settings into the
screenshot's expand-in-place rows: each shows its current value as a
second line under its label with a `⌄` chevron, and tapping the row
expands its option controls in place rather than showing them
permanently on the row.

## Acceptance criteria

- [ ] Appearance (dark mode), Accent color and Language each render as
      a collapsed row: icon, label, current value as a second line
      beneath the label, and a `chevron-down` that rotates when
      expanded. Accent color's value line shows a small dot in the
      currently selected accent alongside its name.
- [ ] Tapping the row expands it in place to reveal that setting's
      existing control — the existing `.tabs`/`.tab-opt` radio groups
      for Accent color and Language, and a comparable option control
      for Appearance — and collapses it again on a second tap.
- [ ] Changing a value updates the collapsed row's value line
      immediately and applies exactly as it does today, via the
      existing `saveSettings()` / `applyTheme()` / `renderChrome()` /
      `renderScreen()` calls. No change to how any of these settings
      are stored.
- [ ] Dark mode keeps working from this row. If it is presented as
      options rather than the current `#darkSwitch` toggle, the
      existing `state.dark` boolean remains the stored value and no new
      persisted field is introduced.
- [ ] Hide amounts stays a plain switch row with no chevron and no
      value line.
- [ ] Expansion state is view-only and resets on re-render — no new
      persisted field, and specifically not a revival of the deleted
      `state.settingsGroupOpen`.
- [ ] Expanded and collapsed rows are keyboard operable and expose
      their expanded state to assistive technology
      (`aria-expanded`).
- [ ] Desktop (1024px+) renders the same rows in its Display pane.
- [ ] `e2e/dark-mode.spec.js` is updated if the toggle's markup
      changes, and still asserts that toggling actually changes the
      rendered theme.
- [ ] New i18n strings for the Appearance row's label and value names
      are added in both languages.
- [ ] Light and dark mode both render correctly.

## UX / design references

- Follow `docs/UX.md`.
- Match existing: today's Accent color / Language rows (`.tabs`/`.tab-opt`
  radio groups, `settings.js`) for the expanded control; the `chevron-right`
  rotation-free drill rows (`settings-drill-row`) are a different pattern
  (navigation, not disclosure) and are not the reference here.
- Reuse: the existing `.tabs`/`.tab-opt` radio group for Accent color and
  Language's expanded control. For the disclosure chevron, rotate the
  existing `chevron-right` icon via CSS `transform` rather than adding a
  new `chevron-down` symbol to `icons/sprite.svg` — the sprite has no
  `chevron-down` today and editing the sprite file has its own documented
  failure mode (`docs/ARCHITECTURE.md`).
- New design primitives required by this ticket: the expand-in-place
  disclosure row itself (subtitle line + rotating chevron) — authorized by
  `docs/specs/settings-chatgpt-style-navigation.md`'s screenshot mockup and
  Appearance/Accent color/Language rows (its `⌄`-chevron rows, ~lines
  126-130).
- Mobile (<1024px) behavior: as described in Acceptance criteria — each row
  collapsed by default, showing icon, label, and current-value subtitle;
  tapping expands the row's existing control in place and collapses it on a
  second tap.
- Desktop (>=1024px) behavior: the same collapsed/expand-in-place rows
  render in the Display pane, per Acceptance criteria.

## Review notes

**Confirmed defects (both fixed before merge):**

- The disclosure CSS included `.settings-disclosure:has(+ .toggle-row) {
  border-bottom: none; }`, which stripped the divider from the row
  immediately before a `.toggle-row` sibling — i.e. the **Language** row,
  not the actual last row (Hide amounts, already correctly handled by the
  pre-existing `.toggle-row:last-child` rule). Verified live via computed
  style before the fix (`border-bottom: 0px none` on Language). Removed
  the extra selector entirely; the pre-existing rule was sufficient.
- `.settings-accent-dot.coral`/`.purple` hardcoded `#cd4805`/`#6247ea`,
  duplicating `theme.js`'s `ACCENT.coral.base`/`purple.base` — the exact
  values already live in `--color-accent`. Since the dot only ever shows
  the *currently selected* accent, changed it to
  `background: var(--color-accent)` with no per-name classes, removing
  the duplication and the future-drift risk.

No optional suggestions were adopted (an unused `darkModeBtn` i18n string
and one redundant CSS selector were noted but left as-is — cosmetic, not
required by any acceptance criterion).
