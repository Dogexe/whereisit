## Goal

Browser Back dismisses the Transactions Filters, Insights Filters, Export and
Import sheets, the same way WI-026 made it dismiss the Add sheet.

## Acceptance criteria

- [x] Each of the four sheets pushes an overlay history entry when it opens and
      releases it when it closes, using WI-026's `src/overlay-history.js`:

      | Sheet | Push at | Release in |
      |---|---|---|
      | Transactions Filters | `transactions.js:326` | `closeTxFilterSheet` (`transactions.js:307`) |
      | Insights Filters | `insights.js:160` | `closeInsightsFilterSheet` (`insights.js:242`) |
      | Export | `export-sheet.js:69` | `closeExportSheet` (`export-sheet.js:47`) |
      | Import | `openImportSheet` (`import-sheet.js:37`) | `closeImportSheet` (`import-sheet.js:47`) |

- [x] Each sheet uses its **own distinct key**, so two keys can never collide
      on the stack.
- [x] The release call goes in the single named close function each sheet
      already funnels every dismissal through — close button, backdrop tap,
      Escape, swipe-down, **and** the action-completed paths
      (`export-sheet.js:82`/`:89`/`:93` after CSV/JSON/Sheets export,
      `import-sheet.js:260` after a commit). No per-path release calls.
- [x] The `onPop` callback is the **named close function**, never a closure
      over a captured backdrop element (see Implementation guidance).
- [x] Back with any of the four open closes that sheet, keeps the URL, and
      stays in the app.
- [x] Every non-Back dismissal of each sheet releases its entry, so a later
      Back is not swallowed — including the action-completed paths. Note
      `history.length` does **not** return to its pre-open value: `history.back()`
      retains the released entry as a *forward* entry. Assert a restored base
      `history.state` and a stable, non-accumulating length across repeated
      open/close cycles, exactly as `nav.spec.js:92-122` does for the Add sheet.
      (WI-026 shipped with this corrected; the original wording specified
      something the History API cannot do.)
- [x] `src/screens/settings.js` is still **not** modified, and
      `e2e/nav.spec.js:124-159` still passes unchanged.
- [x] The Add sheet's behavior from WI-026 is unchanged.
- [x] No new CSS, class, `STRINGS` key, icon, or visible control.
- [x] Existing related behavior remains unchanged.

## UX / design references

- Follow `docs/UX.md`.
- Match existing: WI-026's Add sheet adoption — same push-on-open,
  release-inside-the-close-function shape.
- Reuse: each sheet's existing close function. Back becomes a new caller of
  it, not a new close path.
- New design primitives required by this ticket: **none.** Nothing visual
  changes.
- Mobile (<1024px) behavior: Back closes whichever of the four is open.
- Desktop (≥1024px) behavior: same. Unlike the Add sheet, these four exist at
  every viewport, and Back-dismisses-the-sheet is correct on both — the owner
  is deliberately viewport-agnostic (spec decision 6).

## Implementation guidance

- **Likely files:** `src/screens/transactions.js`, `src/screens/insights.js`,
  `src/screens/export-sheet.js`, `src/screens/import-sheet.js`, plus e2e
  coverage. No new module, no `settings.js`.
- **The shipped API, verified against the merged module:**
  `pushOverlayHistory(key, onPop)` and `releaseOverlayHistory(key)`, both from
  `src/overlay-history.js` (22 lines — read it, it is shorter than this
  bullet). `push` is a no-op if `key` is already on the stack; `release` acts
  only when `key` is the **top** entry and returns `false` otherwise.
- **Existing pattern to reuse:** WI-026's Add sheet wiring, verbatim in shape —
  `pushOverlayHistory("add", closeAddSheet)` at `add.js:583`, the last line of
  `openAddSheet`; `releaseOverlayHistory("add")` at `add.js:590`, the last line
  of `closeAddSheet`. Copy that shape exactly.
- **What WI-026's review found about `onPop`, which applies here.** Because
  `onPop` is the *bare* close function, Back does whatever that function does
  and nothing more — it does not run any wrapper the UI dismissals go through.
  For the Add sheet that meant Back skipped `resetForm()`, judged harmless. The
  equivalent here is Insights: `dismiss` (`insights.js:264`) calls
  `closeInsightsFilterSheet()` *and then* `renderBreakdownFilterSheet()`, so
  Back will behave like the Escape path (`insights.js:248`), which already
  closes without that re-render. That is acceptable precisely because an
  existing path already does it — but confirm it looks right when you drive it,
  and record it in review notes if it does not.
- **Why `onPop` must be the named function, not a closure:** all four sheets
  render inside `#screen`'s `innerHTML`, which `renderScreen()`/
  `renderSettings()` fully rebuild. The open state survives that (the
  `state.*SheetOpen` flag drives the `hidden`
  binding), but the DOM node does not. The 25-second background sync tick
  (`main.js:97`) is *not* the reason, contrary to this ticket's original
  wording: every background re-render caller (`main.js:118`/`:146`/`:163`/
  `:184`/`:188`, `sync.js:579`) is gated on `hasLiveInputRisk()`, which
  already returns `true` for all four of these sheets (`sync.js:509`,
  `sync.js:516`). `renderSettings()`'s own non-sync callers are what keep the
  requirement real. Every close function already looks its
  backdrop up fresh by id and documents why (`transactions.js:304-306`,
  `export-sheet.js:45-46`, `import-sheet.js:45-46`). A captured element would
  be detached and silently do nothing.
- **Insights is the awkward one, in two ways.** Its sheet fully regenerates its
  own markup on almost every field change while open
  (`renderBreakdownFilterSheet`, `insights.js:258`), so nothing may be wired
  once at setup (`docs/ARCHITECTURE.md:89-96`). And it has two close paths that
  differ — `dismiss` (`insights.js:264`) re-renders afterward, the Escape
  listener (`:248`) does not. Both reach `closeInsightsFilterSheet`
  (`:242`), which is why the release call belongs there and nowhere else.
- **Relevant tests:**
  - `e2e/filters.spec.js` — existing Transactions/Insights filter-sheet
    coverage; the natural home for the new assertions on those two.
  - `e2e/csv-import.spec.js` — drives the Import sheet through a real commit,
    which is the `import-sheet.js:260` close path.
  - `e2e/nav.spec.js:124-159` — the Settings sub-page history round trip;
    regression guard that `settings.js` is still untouched. (It moved down
    from `:73-108` when WI-026 inserted its two tests above it.)
  - `e2e/nav.spec.js:73-122` — WI-026's two Add-sheet history tests. These are
    the model to copy for all four sheets here, and a regression guard that the
    Add sheet still works.
- **Do not change:** `src/screens/settings.js`, `router.js`'s `setTab`, the
  Manage sheet, `src/overlay-history.js` itself (if it needs a change, that is
  an escalation, not a quiet edit), or any sheet's dismissal semantics.
- **Escalate back to Claude if:**
  - any of the four turns out to have a dismissal path that does *not* route
    through its named close function;
  - two of these sheets can be open simultaneously (the spec's single-stack
    assumption says they cannot);
  - adopting Insights' sheet appears to require restructuring
    `renderBreakdownFilterSheet`;
  - `src/overlay-history.js` needs an API change to accommodate any of them.

## Review notes

### Confirmed defects

**None.** Every acceptance criterion was met by the first implementation pass,
and the full gate passed on it unchanged.

### Verified, not defects

- **The Insights `onPop` asymmetry this ticket asked to be confirmed.** Back
  runs the bare `closeInsightsFilterSheet` and therefore skips the
  `renderBreakdownFilterSheet()` that the `dismiss` closure (`insights.js:266`)
  runs after closing. Driven and confirmed **visually identical**:
  `closeInsightsFilterSheet` already hides the live backdrop node it looks up
  by id, and every filter mutation inside the sheet re-renders the toolbar and
  content itself, so that trailing re-render only rebuilds already-hidden
  markup. Matches the Escape path, as predicted. Nothing to change.
- **`settings.js`'s state-blind `popstate` listener cannot fire for these four.**
  This is the hazard the spec warns about once a second pusher exists.
  `SETTINGS_SUB_PAGE_IDS` (`settings.js:156`) is
  `budgets/bills/goals/categories/accounts/security` — **`sync` is not a
  sub-page**, so the Export and Import buttons sit on the Settings root with
  `state.settingsSubPage === null` and the listener returns early. On desktop it
  returns early unconditionally. Now asserted rather than reasoned: all five new
  e2e tests run at 390x844, where that mechanism is live.
- **No co-open.** None of the four can be open alongside each other, the Add
  sheet, or a Settings sub-page. `.filter-sheet-backdrop` is
  `position:fixed; z-index:50` (`styles.css:553`), above `.tabbar-wrap`'s 30 and
  the un-z-indexed sidebar, so every other entry point sits behind the backdrop;
  and `settings.js:489-490` only wires the two Settings sheets when their open
  buttons are actually rendered. The escalation criterion did not trigger.
- **Re-entrancy on Back and on double-close.** `popstate` pops the stack before
  calling `onPop`, so the close function's own `releaseOverlayHistory` finds a
  non-matching top, returns `false`, and issues no second `history.back()`. The
  same ordering covers a swipe-down commit followed by a backdrop click.
- **Every dismissal routes through the named close function.** Verified across
  all 15 call sites — close button, backdrop tap, Escape, `wireSheetDrag`, and
  the four action-completed paths (`export-sheet.js:84`/`:91`/`:95`,
  `import-sheet.js:263`). Zero per-path release calls.

### Optional suggestions — all applied in a follow-up round

1. The four new tests originally ran only at the default desktop viewport
   (1280x900), where `settings.js`'s history mechanism is disabled by
   `isDesktopShell()`. Now all set 390x844, matching WI-026's Add-sheet tests
   and the viewport the audit's D3 finding was measured on.
2. The post-`goBack()` assertions checked only backdrop-hidden and an unchanged
   URL. Added an explicit `#screen` visibility check — landing on `about:blank`
   was the exact failure the audit recorded.
3. Only the close button was exercised as a non-Back dismissal. Added Escape
   coverage for the Insights sheet, whose Escape path differs from its `dismiss`
   path.
4. The Export sheet's action-completed closes had no coverage. Added a fifth
   test driving the real CSV export and asserting the base `history.state` is
   restored after it.
5. This section and the ticket's checkboxes were left blank by the
   implementation pass; filled in here.

### Correction to this ticket and the spec

Both justified the named-`onPop` requirement with the 25-second background sync
tick rebuilding `#screen`. That rebuild **cannot reach these four sheets**:
`hasLiveInputRisk()` already returns `true` for `importSheetOpen`
(`sync.js:509`) and for
`txFilterSheetOpen`/`insightsFilterSheetOpen`/`exportSheetOpen`
(`sync.js:516`), and every background re-render caller (`main.js:118`/`:146`/
`:163`/`:184`/`:188`, `sync.js:579`) is gated on it. The requirement itself
stands — `renderSettings()` has non-sync callers — so only the stated rationale
changed, in this ticket's Implementation guidance and in
`docs/specs/back-button-dismisses-overlays.md`'s Release 2 section. Corrected so
`WI-028` does not inherit the wrong reasoning.
