# WI-014 — Visible focus indicators for the fourteen controls that lack them

Status: Completed

Merged in commit `f2bec1d` (pushed to `main` alongside `WI-013`),
deployed, and confirmed live at `https://dogexe.github.io/whereisit/`
(`button.toggle-row:focus-visible` present in the deployed
`styles.css`).

Spec: `docs/specs/accessible-names-and-focus-indicators.md`

Codex profile: terra-medium

## Goal

Give every interactive control a visible keyboard focus indicator, using the
canonical treatment that eleven controls already use. No new visual
primitive, and no change for mouse or touch users.

## Acceptance criteria

- [ ] These fourteen controls paint the canonical focus outline when reached
      by keyboard: `.nav-btn` (covers both the tab bar and the sidebar),
      `.tab-opt`, `.switch`, `button.toggle-row`, `.home-profile-btn`,
      `.toast-undo-btn`, `.shortcut-btn`, `.period-pill button`,
      `.picker-year-row .step`, `.picker-year-heading`, `.picker-month-cell`,
      `.filter-field-label button`, `.kind-toggle button`.
- [ ] The treatment is the existing accent outline, matched exactly to the
      eleven current `:focus-visible` rules — no new color, width, offset,
      radius, or shadow (spec Decision 2.1).
- [ ] `.tab-opt` rings the visible label via `:has(input:focus-visible)`,
      not the visually hidden radio (spec Decision 2.2). Verified on all six
      `role="radiogroup"` controls.
- [ ] `button.toggle-row`'s ring is confirmed to actually paint despite its
      `all: unset`, **in a real browser** (spec Decision 2.3).
- [ ] `.filter-checkbox-row`'s native checkbox ring is checked in a real
      browser; either left unchanged with that finding recorded in the
      spec's Decision 2.4, or given the same `:has()` treatment if it is not
      adequate.
- [ ] `.date-native-overlay` is left exactly as it is — already
      `tabindex="-1" aria-hidden="true"`, correctly outside the tab order.
- [ ] Nothing changes at rest: no rendered difference for a mouse or touch
      user, mobile and desktop, light and dark, Thai and English.
- [ ] Existing related behavior remains unchanged — no control changes what
      it does, and no existing `:focus-visible` rule is altered.

## UX / design references

- Follow `docs/UX.md`.
- Match existing: the eleven `:focus-visible` rules already in
  `styles.css` (`.btn`, `.category-chip`, `.settings-nav-item`, etc.).
- Reuse: the canonical accent outline; `:has()`, already used three times in
  this stylesheet.
- New design primitives required by this ticket: none.
- Mobile (<1024px) behavior: applies to the tab bar, sheets, and the
  swipe-row surfaces; a keyboard is less common here but the rules are
  shared, so they must not regress touch rendering.
- Desktop (>=1024px) behavior: this is the primary case — sidebar nav,
  settings rows, pickers, and popovers are all keyboard-reachable.

## Verification

- [ ] E2E: each of the fourteen controls is focused **the way a keyboard
      user reaches it**, and a painted outline is asserted. Reuse the
      computed-style geometry pattern in
      `e2e/add-sheet-keyboard-ghosting.spec.js` rather than inventing a new
      assertion shape.
- [ ] Do not assert by calling `.focus()` alone — `:focus-visible` depends
      on interaction modality, so a programmatic focus can paint a ring that
      real `Tab` navigation never produces, and the test would pass while
      the feature stays broken for a real keyboard user.
- [ ] Manual real-browser check for Decisions 2.3 and 2.4, light and dark.
- [ ] `npm test`
- [ ] `npm run test:e2e`
- [ ] `npm run build`
- [ ] Complete diff inspected for unrelated changes.

## Out of scope

- Accessible names — that is WI-013.
- Any token, spacing, color, or radius normalization. All eight of
  `docs/UX.md`'s open design decisions stay open; this ticket resolves none
  of them.
- Focus-ring contrast against every possible surface. The accent outline is
  the documented treatment, used unchanged; a low-contrast placement would
  be a new finding, not part of this work.
- A general WCAG audit. This closes one enumerated defect.

## Dependencies

None. Independent of WI-013, though both touch `.nav-btn` — implement
sequentially, not in parallel.
