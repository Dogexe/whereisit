## Goal

A never-touched install shows no budgets and no bills it invented, and the
two surfaces that go empty as a result render a proper empty state instead
of a blank card.

## Acceptance criteria

- [x] `src/state.js`'s `budgets` and `bills` initialise to `[]`, matching the
      adjacent `goals` export.
- [x] On a fresh profile, Home renders **no** upcoming-bills section (already
      guarded) and **no** empty white card under "งบประมาณเดือนนี้" — instead
      the budget card contains a plain `.empty-note` reading `l.noBudgets`.
- [x] Home keeps its budget section heading and its "See all" button when

## Implementation guidance

- **Likely files:** `src/state.js` (seed arrays, lines 121-132),
  `src/screens/home.js` (budget card, lines 275-281),
  `src/screens/insights.js` (`renderBudgetsContent`, lines 75-94),
  `e2e/manage-row-swipe.spec.js`, `e2e/nav.spec.js`, `e2e/helpers.js`.
- **Likely functions/modules:** `renderHome()`'s budget-card template;
  `renderBudgetsContent()` in `insights.js`. Both currently do
  `rows.map(...).join("")` with no empty fallback — that is the whole bug.
- **Existing pattern to reuse:** `settings.js:187` —
  `budgets.map(budgetRowHtml).join("") || \`<div class="empty-note">${escapeHtml(l.noBudgets)}</div>\``.
  The `|| fallback` on the joined string is the idiom used throughout this
  codebase; copy it rather than adding an `if`.
- **For the e2e fixture:** `e2e/helpers.js:57` `createAccount()` is the model
  for a "create this through the real UI" helper — same shape, same
  `navBtn` + `openSettingsSection` opening, then form fill and save. The
  budget form's ids are `#addBudgetBtn`, `#budgetCategorySelect`,
  `#budgetLimitInput`, `#saveBudgetFormBtn`
  (`src/screens/settings-budgets.js:33-36`). Prefer adding a `createBudget()`
  helper there over duplicating the steps in two specs.
- **Relevant tests:**
  - `tests/derived.test.js` — builds its own budget fixtures via
    `setBudgets(...)` at lines 155 and 173, so it should need **no** change.
    If it does, the change went wider than intended.
  - `e2e/manage-row-swipe.spec.js:40-43` — **breaks without a fix.** Opens
    Settings → Budgets and grabs the first `[data-delete-budget]` row.
  - `e2e/nav.spec.js:85` — **breaks without a fix.** Asserts
    `.manage-row-wrap` is visible in the budgets sub-page.
  - `e2e/transactions-crud.spec.js:16-17` — does **not** break, but its
    comment explains a `.list-card` scoping choice by referring to "the
    seeded sample bills". Update the comment; leave the scoping alone, it is
    still correct.
- **Known invariants:**
  - `restore.js:15` — a saved array always wins over the module default;
    only an absent settings key falls through. This is what makes the change
    safe for existing users, and it must not be touched.
  - `sync.js:176-183` (`markAllPending`) and `sync.js:219-226` (backfills)
    map over these arrays and guard pushes with `if (changed*.length)`, so
    empty arrays are a no-op. No tombstone is generated for a row that never
    existed.
- **Do not change:** `restore.js`, `storage.js`, any `*ToRow`/`rowTo*`
  mapper, the default categories list, the default account, `markBillPaid`,
  or the `.empty-note` / `.empty-note-search` CSS rules.
- **Escalate back to Claude if:**
  - a unit test in `tests/` needs changing to make this pass;
  - removing the seeds appears to push deletions or tombstones for `budgets`
    or `bills` on sign-in;
  - either empty state seems to need a new CSS rule or a new `STRINGS` key
    to look right;
  - the Insights empty state cannot be made mutually exclusive with the
    unbudgeted-spending card without restructuring `renderBudgetsContent()`.

## Review notes

One confirmed defect, fixed. Insights' `.empty-note` was first emitted as a
direct child of `.insight-cards`, which `styles.css:1268`/`:1307` turn into
a 2- then 3-column grid from 880px up. The note therefore occupied only the
first grid column, and its `text-align: center` centered it inside that
column rather than the panel — measured against a real `dist/` build on a
fresh profile at 350.66px wide in a 1080px panel, ~365px left of the panel
center. That contradicted this ticket's "plain centered empty note" and
"Desktop (≥1024px) behavior: identical to mobile". Fixed by rendering the
note as a sibling *before* `.insight-cards`, the way `.insight-rollup`
already sits outside it — no new CSS rule, class, or string, as required.

The same round also strengthened the new e2e assertion, which originally
only checked `toBeVisible()` and so passed on the broken layout. It now
requires the note to be a direct `#budgetsContent` child and its horizontal
center to be within 2px of the panel's. Confirmed as a real guard by
reverting the fix, rebuilding, and watching the test fail, then restoring.

Optional suggestions, raised and deliberately **not** adopted: making
`createBudget()`'s closing `toHaveCount(1)` assertion reusable for a second
budget; adding a comment to `nav.spec.js` explaining why it reloads after
creating its budget; and a cosmetic nit that `.insight-cards` still renders
as an empty container (carrying its `padding-bottom: 16px`) when the note
shows — it has no background or border, so there is no visible artifact.

Verification note: Codex reported the e2e run as blocked on a missing
Playwright Chromium. That was specific to its own sandbox — the browser is
present locally, and the full gate was re-run to completion during review:
`npm test` 173/173, `npm run test:e2e` 33/33, `npm run build` pass.
