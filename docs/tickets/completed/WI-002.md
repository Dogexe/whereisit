# WI-002 — Move Add-sheet commit preview to the top

Status: Completed

Spec: `docs/specs/add-sheet-preview-position.md`

## Goal

In the mobile Add/Edit bottom sheet only (`src/screens/add.js`,
`renderAddSheet`), move the commit preview (`#addCommitPreview`) from the
last field (just above the sticky Save button) to the first field, above
Amount, so it's visible while filling out the form rather than only as a
final check before Save. Add an empty-state guard so it doesn't show a
meaningless `฿0.00` default before a real amount is entered. Desktop's
full-page Add/Edit form is untouched.

## Acceptance criteria

- [x] In `addFormFieldsHtml`'s `isSheet` branch, `commitPreviewField` is the
      first entry in `fieldsInOrder`, before `amountField` (currently last,
      after `noteField`). The non-sheet (desktop) `fieldsInOrder` array is
      unchanged.
- [x] `renderCommitPreview()` sets `el.hidden = true` and returns (without
      building `innerHTML`) whenever `parseFloat($("txAmount").value) || 0`
      is `<= 0`, for both the transfer and non-transfer branches. It sets
      `el.hidden = false` and renders normally once amount is `> 0`.
- [x] Opening the Add sheet fresh (new transaction, no amount entered yet):
      the preview is not visible. Typing a positive amount makes it appear
      at the top of the sheet, above Amount.
- [x] Opening the Edit sheet on an existing transaction (amount already
      populated and > 0): the preview is visible immediately at the top,
      showing that transaction's current category/account/amount.
      (Verified by code reasoning, not a live click-through — see Review
      notes.)
- [x] Clearing the amount back to empty/0 after it was shown hides the
      preview again; re-entering a positive amount shows it again.
- [x] Changing category, account, or type (including Transfer, which uses
      the from/to account branch) still live-updates the preview content
      exactly as before — only its visibility condition and DOM position
      changed, not its content logic.
- [x] The two stale comments describing the old "last field, before Save"
      rationale (`addFormFieldsHtml`'s field-order comment near
      `commitPreviewField`, and `renderCommitPreview`'s leading comment)
      are rewritten to describe the new placement and the empty-state
      guard.
- [x] Desktop (`!isSheet`, `renderAdd`) is visually and behaviorally
      unchanged — no preview element, same field order as before.
- [x] Existing related behavior remains unchanged (form validation,
      category guessing, date typing/parsing, transfer swap, save/cancel).

## Review notes

**No confirmed functional defects.** The implementation matches the spec:
`commitPreviewField` moved to the front of the sheet's `fieldsInOrder`,
`renderCommitPreview()` hides the element (and clears its children so the
pre-existing `.commit-preview:empty { display: none; }` CSS rule wins over
the `.commit-preview { display: flex; }` author rule — `[hidden]` alone,
being a UA-stylesheet rule, would otherwise lose that specificity fight)
whenever amount is `<= 0`, and both stale comments were rewritten
accurately. Independently re-ran `npm test`/`npm run build` and did a live
browser check against built `dist/` (DOM order, hide/show on amount
changes, transfer branch content, desktop untouched) — all matched Codex's
report.

accurate but out of this ticket's stated scope ("implement only this
