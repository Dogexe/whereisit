# WI-020 — Home header: greeting + date, drop "Overview"

Status: Ready

Spec: `docs/specs/home-header-greeting.md`

Codex profile: terra-medium

Risk tier: Low

## Goal

Replace Home's static `"{Month Year}"` / `"Overview"` header with a
time-of-day-varied greeting (using the signed-in display name) on row one
and the existing date string moved to row two.

## Acceptance criteria

- [ ] Row 1 of `.home-header-row` renders a greeting string built as
      `"{Greeting}, {name}"` when signed in, or just `"{Greeting}"` when
      signed out (no dangling comma).
- [ ] Greeting picks one of 2-3 phrasings per time-of-day bucket
      (morning/afternoon/evening, by local hour), randomly, once per Home
      render — per the spec's decision 4 buckets/hours.
- [ ] Name comes from `accountDisplayName(currentUser, l.notSignedIn)`
      (`home.js:108`), reused as-is — no second name source introduced.
- [ ] Row 2 renders the existing `today` date string (`home.js:93`)
      unchanged in format, just relocated.
- [ ] `l.overview` is removed from Home's render; the i18n key itself is
      only deleted from `i18n.js` if no other caller references it
      (grep first).
- [ ] New greeting strings follow the existing `key: [th, en]` tuple
      convention in `i18n.js`.
- [ ] Existing related behavior remains unchanged: profile avatar button,
      its click handler, and `.home-header-row` layout/spacing otherwise
      untouched.

## UX / design references

- Follow `docs/UX.md`.
- Match existing: Home's `.home-header-row` (`src/screens/home.js`,
  `styles.css`).
- Reuse: `accountDisplayName()`, the existing `today` date computation,
  the `i18n.js` tuple convention.
- New design primitives required by this ticket: none.
- Mobile (<1024px) behavior: identical to desktop — no viewport branching.
- Desktop (>=1024px) behavior: identical to mobile.

## Implementation guidance

- Likely files: `src/screens/home.js` (render + greeting logic),
  `src/i18n.js` (new greeting string keys).
- Likely functions/modules: `renderHome()` (`home.js:69-119`).
- Existing pattern to reuse: `i18n.js`'s `key: [th, en]` tuple format
  (e.g. `overview: ["ภาพรวม", "Overview"]` at `i18n.js:7`); the existing
  `today` computation at `home.js:93`.
- Relevant tests: check for any existing unit test touching
  `renderHome()`/Home screen rendering before assuming none exists.
- Known invariants: `.home-header-row` currently renders unconditionally
  on every `renderHome()` call — the greeting must compute cheaply and
  synchronously (no async name/time lookup).
- Do not change: `accountDisplayName()`, `currentUser`, the profile
  avatar button's markup/handler.
- Escalate back to Claude if: `l.overview` turns out to be referenced by
  another screen (spec assumed Home-only usage but didn't exhaustively
  verify every caller).

## Review notes

**Confirmed defect (visual hierarchy reversed):** the shipped code gives
the greeting the large/bold `.screen-title` style and the date the
small/muted `.today-label` style. Per the maintainer's annotated mockup
(`E:\design\UPmP7gus.jpg`, re-checked directly), it should be the reverse:
greeting stays small/muted (row 1), date stays large/bold (row 2) — only
the text content of each row changes, not which style it carries. The
originating spec's decision 2 had this backwards from a misreading of the
mockup; spec corrected. Fix: swap which element gets `.screen-title` vs
`.today-label` in `home.js`'s render (greeting → `.today-label`'s
treatment, date → `.screen-title`'s treatment), keeping greeting-then-date
row order.

**Confirmed defect (wrong element tags, not just classes):** the sizing
fix above swapped which class (`.today-label` / `.screen-title`) each
line uses, but left the original tags in place (`<h2>` for greeting,
`<div>` for date). `styles.css:167` has `h1, h2, h3, h4 { font-weight:
800; letter-spacing: -0.02em; margin: 0; }`, which applies by tag name —
so the greeting (now `<h2 class="today-label">`) incorrectly inherits the
800-weight/tight-tracking heading treatment, and the date (now `<div
class="screen-title">`) incorrectly loses it, looking thin instead of
bold. Every other `.screen-title` usage in the codebase (`add.js:522`,
`insights.js:21`, `transactions.js:354`) is an `<h2>` — home.js's date
line should match. Fix: swap the tags back to their original
pairing — greeting → `<div class="today-label">` (no inline margin, as
`.today-label` had pre-ticket), date → `<h2 class="screen-title"
style="margin:2px 0 var(--space-sm)">` (keep the inline margin that was
on this element pre-ticket) — only the text content moves, not the
tag/class/inline-style pairing.

**Also reported (likely the same root cause):** the profile avatar icon
looks misaligned against the two text lines. `.home-profile-btn`'s
`margin-top: 2px` (styles.css) was tuned against the original div-then-h2
line-height rhythm; restoring the correct tags above should also fix this
alignment. Verify visually (both signed-in/out, a couple of names of
different length) after the tag fix, since the two issues may not be
fully the same cause.

No other suggestions.
