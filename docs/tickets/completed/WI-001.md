# WI-001 — Transactions search bar restyle

Status: Completed

Spec: `docs/specs/transactions-search-bar-restyle.md`

## Goal

Restyle the Transactions screen's search + Filters row: a wider search
field with a decorative magnifying-glass icon on the left and a
conditional clear ("x") button on the right, and a Filters button
collapsed from icon+text+badge to icon+badge only (round icon button).
Visual/interaction-only change — no filtering logic changes.

## Acceptance criteria

- [x] `#txSearchInput` renders with a decorative `search` icon (reused from
      `icons/sprite.svg` via `icon("search")`) positioned inside its left
      edge, at every screen width, in both light and dark mode.
- [x] A clear button (`&times;` glyph, matching the existing sheet-close
      button convention — not a new SVG icon) renders inside the input's
      right edge. It has the `hidden` attribute whenever `state.txSearch`
      is empty, and no `hidden` attribute once there is any text — kept in
      sync on every relevant re-render (initial render and the existing
      `input` listener).
- [x] Clicking the clear button sets `state.txSearch = ""`, re-renders the
      filtered transaction list (same effect as clearing the field by
      hand), and returns keyboard focus to `#txSearchInput`.
- [x] Typing in `#txSearchInput` still live-filters the list exactly as
      before (no change to `filteredTxList()`).
- [x] `#openTxFiltersBtn` no longer renders the `<span>Filters</span>` text
      node. It keeps `icon("filter")` and `#txFiltersBadge` (unchanged
      badge show/hide logic via `updateFiltersBtnBadge()`), and becomes a
      round icon-only button (fixed width/height, `border-radius: 50%`)
      instead of the current rectangular `btn btn-secondary` pill.
- [x] `#openTxFiltersBtn` gets an `aria-label` (new i18n string
      `filtersBtnAria`) since its visible text is gone.
- [x] The new clear button gets an `aria-label` (new i18n string
      `clearSearchAria`).
- [x] Insights' Breakdown tab Filters button (`#openInsightsFiltersBtn`,
      `.toolbar-row` in `src/screens/insights.js`) is untouched — no text
      change, no shape change. (Required one round of fix; see Review notes.)
- [x] `wireFilterSheet()`, the active-filter-chips row, and
      `filteredTxList()` are unchanged.
- [x] Existing related behavior remains unchanged (Filters sheet
      open/close, active-filter chips, badge count, search-as-you-type).

## Review notes

**Confirmed defect (fixed):** the original implementation deleted the
shared bare `.filters-btn { position: relative; }` rule in `styles.css`
(which both Transactions' and Insights' Filters buttons relied on for their
`.filter-badge` child's absolute positioning) and replaced it with a
Transactions-scoped `.tx-toolbar-row .filters-btn { position: relative; ... }`
rule only, without restoring the equivalent for Insights'
`.toolbar-row .filters-btn`. This broke Insights' Breakdown-tab active-filter
badge: verified live in a browser that with a category selected,
`#insightsFiltersBadge` rendered at `{x: 1510.8, y: -6}` (pinned to the
viewport's top-right corner, clipped off-screen) instead of anchored to
`#openInsightsFiltersBtn` (`position: static`). Directly violated this
ticket's "Insights' Breakdown tab Filters button is untouched" requirement.

Fix: added `position: relative;` to the existing `.toolbar-row .filters-btn`
rule (`styles.css` line 718) rather than reintroducing a shared bare rule —
smaller, more localized diff. Re-verified live: `getComputedStyle` now
reports `position: relative` on the button and the badge's bounding rect is
correctly anchored to the button's top-right corner. `npm test`/
`npm run build` re-run clean after the fix; full `npm run test:e2e` (run
locally, outside Codex's sandbox) also passed 15/15 after the fix.

No optional suggestions raised — the diff otherwise matched the spec
directly.

**Unrelated, pre-existing state (not from this ticket):** `CLAUDE.md` and
`docs/CHANGELOG.md` carried uncommitted changes from an earlier, separate
session that set up this repo's `docs/WORKFLOW.md`/`AGENTS.md`/tickets
scaffolding, predating WI-001. Codex correctly identified these as
unrelated and left them untouched rather than folding them into this
ticket's diff.
