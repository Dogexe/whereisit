# WI-006 — Icon + color on the Add form's Type segmented control

Status: Completed

Spec: `docs/specs/type-selector-icon-color.md`

Codex profile: terra-medium

## Goal

Give the Add/Edit form's Type field (Expense/Income/Transfer,
`.tabs.block`/`.tab-opt` in `add.js`/`styles.css`) an icon and a
per-segment semantic color on its active state, reusing this app's own
existing income/expense/transfer icon and color conventions instead of
inventing new ones. Applies to both the mobile Add sheet and the desktop
full-page form (one shared render function).

## Acceptance criteria

- [x] Each Type segment (Expense/Income/Transfer) renders a small leading
      icon: expense → `arrow-up-right`, income → `arrow-down-left`,
      transfer → `arrow-right-left` (matching `screens/home.js:137,142`
      and `screens/tx-row.js:53`'s existing usage of these same icons for
      the same meanings).
- [x] `rowTone(type)` in `categories.js` is extended to handle all three
      types explicitly (income / expense / transfer), replacing its
      current two-way `income` vs. everything-else split. `transfer`
      gets a new, distinct tone using a new `--color-chart-5-tint` token
      (`color-mix(in srgb, var(--color-chart-5) 12%, white)`, same
      pattern as the existing income/expense tint tokens) with a new
      fixed `--color-chart-5-tint-fg` as the foreground/active color.
      `income` and `expense` keep returning exactly what they return
      today.
      - **Amended during review, with maintainer approval.** This
        criterion originally called for `--color-chart-5` itself as the
        foreground; that shipped at 1.66:1 in dark mode, because
        `theme.js:67` brightens `--color-chart-5` to `#4fd6c4` while the
        tint keeps mixing toward white in both themes. The fix follows
        the pattern `styles.css`'s `--color-income-tint-fg` comment
        already documents: a fixed, theme-invariant dark hex. Whatever
        hex is chosen must measure at least 4.5:1 against
        `--color-chart-5-tint` in both themes.
- [x] The active segment (`.tab-opt:has(input:checked)`) is tinted with
      that segment's own `rowTone()` result instead of today's flat
      `--color-card`/`--color-text` active style. Inactive segments are
      unaffected (still muted, no color) — only the selected segment is
      tinted.
- [x] Both the mobile Add sheet (`renderAddSheet`) and the desktop
      full-page form (`renderAdd`) show the new icons/colors identically,
      since both go through the same `addFormFieldsHtml()`.
- [x] Existing related behavior remains unchanged: `state.formType`
      transitions, form validation, `updateFormTypeVisibility()`, and
      every other Add-form field are untouched.
- [x] Documented side effect, not a bug: because `rowTone()` is shared,
      existing transfer transaction rows (`tx-row.js`) now render with
      the new teal tint instead of the old accent tint they incidentally
      shared with expense rows. Income and expense rows must be
      pixel-identical to before.
- [x] Second side-effect surface, found during review: `add.js`'s
      `renderCommitPreview()` already called `rowTone(state.formType)`
      before this ticket, so the mobile Add sheet's commit-preview icon
      avatar goes teal for transfers too. Expected and correct — no code
      change of its own, recorded here because the ticket's Out-of-scope
      section asked for extra `rowTone()` callers to be reported rather
      than folded in silently.
- [x] The three Type segments are equal-width with no gaps between them
      (`.tabs.block:has(.type-tab-opt)` + `flex: 1 1 0`), scoped so other
      `.tabs.block` rows are untouched. Added on maintainer feedback that
      the segments sat too far apart on the desktop form.

## Review notes

Record confirmed defects and their resolution here. Keep optional suggestions
clearly separate.

### Confirmed defects (round 1)

1. **Transfer's active label was unreadable in dark mode.** Measured on
   the rendered control: expense 4.89:1, income 4.86:1, transfer
   **1.66:1**; light mode transfer measured 4.24:1, also under AA. Cause
   was this ticket's original acceptance criterion naming
   `--color-chart-5` as the foreground — `theme.js:67` brightens it to
   `#4fd6c4` in dark mode while the tint keeps mixing toward white.
   Resolved by amending that criterion (see above) and adding a fixed
   `--color-chart-5-tint-fg: #17665c` (5.78:1 light / 6.32:1 dark).
   Fixing `rowTone("transfer")` covered transfer transaction rows and
   the commit preview at the same time.
2. **Undocumented third `rowTone()` caller.** `add.js:215`'s
   `renderCommitPreview()` already called `rowTone(state.formType)`.
   Reported rather than folded in, per Out of scope; recorded as a
   side-effect surface in the acceptance criteria above. No code change
   needed beyond defect 1's fix.

### Maintainer feedback (round 1)

- The three segments sat too far apart on the desktop form. Traced to
  `.tabs.block { justify-content: space-between }` with `flex: 0 1 auto`
  cells; fixed with equal-width cells scoped to this row only.

### Process note

The ~310-320px narrow-width check could not be completed manually —
browser window resizing did not take effect in the review environment, so
only full-width was observed. Converted to a Playwright viewport test
(`e2e/type-selector-icon-color.spec.js`) rather than retried by hand,
which also covers the contrast measurement that a screenshot missed.
