# WI-009 — Settings visual language: centered profile, grouped cards, flat icons, Log out row

Status: Completed

Spec: `docs/specs/settings-chatgpt-style-navigation.md`

Codex profile: terra-medium

## Goal

Apply the reference screenshot's visual language to the structure
`WI-008` produced: a centered profile header, gray section labels above
grouped rounded cards, flat monochrome outline icons on Settings' own
chrome rows, and a red Log out row at the bottom. Presentation only —
no navigation or behavior changes.

## Acceptance criteria

- [ ] The screen title (`<h2 class="screen-title">Settings</h2>`) and
      the left-aligned `.profile-row` are replaced by a centered header:
      a 72px round avatar (Google photo, or the name's first initial on
      a neutral background) with the display name centered beneath it.
- [ ] Signed out, the same header shows a neutral placeholder avatar,
      the existing "not signed in" label, and the existing
      Sign-in-with-Google button. No ✎ edit badge is rendered in either
      state.
- [ ] Sign-out moves out of the header into a standalone row at the
      bottom of the root list, rendered only when signed in: a
      `log-out` icon and the existing `signOutBtn` label, both in the
      app's expense/destructive red, in its own card. It calls the
      existing `signOutUser()` with no change to that function.
- [ ] The root list is grouped into visually separate rounded cards
      with the existing `.settings-section-label` above each labeled
      group, matching the layout in the spec's "Root list" diagram.
- [ ] The groups appear in the spec diagram's order, top to bottom:
      **Display**, then **Sync & Data**, then **Manage**, then the
      unlabeled App lock + Privacy policy card, then the Log out card.
      Within Manage the order is Budgets, Bills, Goals, Categories,
      Accounts. This ordering is the "arrange Settings by hierarchy"
      request — everyday appearance settings first, data and device
      settings next, the record types the user manages after that, and
      the rarely-touched account/legal/exit rows last.
- [ ] Settings' own chrome rows (Display, Sync & Data, the Manage
      navigation rows, Security, Privacy policy, Log out) render a bare
      `icon()` glyph instead of `iconAvatar()`'s tinted circle. The
      individual Budget / Bill / Category / Account / Goal *data* rows
      inside each Manage sub-page keep their existing icon avatars
      unchanged (`docs/specs/settings-manage-row-icons.md`).
- [ ] The existing footer privacy-policy link becomes a real tappable
      row in the same card style as every other row — the same row
      primitive the Log out row uses, not a text link — keeping its
      `target="_blank" rel="noopener"` and an external-link affordance
      distinct from the `›` used by sub-page rows. It is a normal row,
      not a destructive/red one; only Log out is red. The footer note
      itself stays at the bottom.
- [ ] Every new gap, padding and radius comes from the existing
      `--space-*` / `--radius-*` scales. No new spacing or radius
      values are introduced.
- [ ] Retired CSS is deleted rather than left dead: `.settings-group`,
      `.settings-group summary`, `.settings-group-body`,
      `.settings-badge-count`, and `.profile-row` if nothing else uses
      it. Confirm by grep before deleting.
- [ ] **WI-005's swipe CSS is preserved untouched**, despite sitting in
      the same region of `styles.css` as the rules being retired above:
      `.manage-row-wrap`, `.manage-row-content` / `.goal-card-top-content`
      (the translating layer, including its opaque
      `background: var(--color-card)`), `.manage-row-actions-group`, and
      every `.manage-swipe-*` rule. These carry the shipped swipe
      behavior for the Manage rows that now live on sub-pages — deleting
      or restyling them silently regresses WI-005. If the new card
      background token differs from `--color-card`, the translating
      layer's background must be updated to match it, or the action
      buttons will show through the row during a drag.
- [ ] Desktop (1024px+) gets the same visual language — restyled nav
      column and detail panes — and its master–detail behavior is
      unchanged.
- [ ] Light and dark mode both render correctly.
- [ ] Every Settings action still works, unchanged.

## Review notes

Implemented by Codex under this ticket's `terra-medium` profile. Codex
could not write to this file itself (`apply_patch` failed repeatedly on
it across two separate runs, while the same file edited fine from the
verifying session), so these notes were transcribed from its reports and
from independent verification.

### Confirmed defects

- **Log out text lost its red to the generic row reset.** Found by Codex
  during its own live pass. `button.toggle-row`'s `all: unset` was
  overriding the destructive color. **Resolved** by scoping
  `.settings-logout-row, button.settings-logout-row` to
  `--color-expense-700`, with the icon forced to match.
- **Privacy policy rendered twice on mobile.** Found by Codex during its
  own live pass. **Resolved**; verified independently afterwards —
  exactly one `a[href*="privacy"]` exists on the mobile root list, with
  `target="_blank"` and `rel="noopener"` intact.
- **Light-mode section labels failed the ticket's 4.5:1 text
  threshold.** Found by independent verification, not by the
  implementing agent. Codex reported "4.66" for "flat icon / label", but
  that figure is the row *icon* measured against the white card; the
  section labels sit **above** the cards on the page background
  (`--color-bg`, `#f6f6f8`), which is darker than the card. Measured
  against the background they actually render on, `--color-muted`
  (`#71747f`) gave **4.32:1**, below the required 4.5:1. Dark mode was
  never affected. **Resolved** by darkening only that label toward the
  text color — `color-mix(in srgb, var(--color-muted) 92%,
  var(--color-text))` — which introduces no new hardcoded color value
  and keeps the label visually subordinate to row text. The palette has
  no intermediate token here: `--color-tertiary` is lighter and worse,
  `--color-text` is far too heavy for a small uppercase label.

### Contrast, measured live in both themes (after the fix)

Measured against a served `dist/` build with `getComputedStyle`, proper
alpha compositing, and a relative-luminance calculation. Note that
`color-mix` computes to CSS `color(srgb …)` whose components are 0–1,
not 0–255 — a measurement script that assumes `rgb()` will silently
produce nonsense for this label.

| Theme | Section label (≥4.5) | Row icon (≥3.0) | Log out text/icon (≥4.5) |
|---|---:|---:|---:|
| Light | 4.32 → **4.82** | 4.66 | 5.64 |
| Dark  | 6.98 → **7.56** | 6.59 | 6.45 |
